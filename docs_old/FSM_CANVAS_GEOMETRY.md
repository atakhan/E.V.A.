# Геометрическая основа и маршрутизация визуального конструктора FSM

**Версия:** 1.0  
**Статус:** канон геометрии холста (проектирование → реализация v1)  
**Назначение:** редактор, в котором пользователь визуально конструирует FSM, а система автоматически поддерживает корректное отображение блоков, переходов и подписей.

Смысловой канон конструктора: [`SKILLS_CONSTRUCTOR.md`](./SKILLS_CONSTRUCTOR.md).  
Исполняемая FSM: [`SKILLS_SPEC_v0.1.md`](./SKILLS_SPEC_v0.1.md).  
Визуальный язык: [`FSM_CANVAS_STYLE.md`](./FSM_CANVAS_STYLE.md).

---

## 0. Привязка к E.V.A.

Это **не** универсальный редактор блок-схем и **не** возврат Behavior Graph (`wait` / `do` / `decide`).

На холсте v0.1:

| ТЗ | E.V.A. |
|---|---|
| Узел (`Node`) | состояние FSM (`FsmState`) |
| Порт (`Port`) | магнитная точка на стороне прямоугольника: `side` + `anchor` (`0.25` / `0.5` / `0.75`). Идентификатор: `{side}:{anchor}` |
| Связь (`Connection`) | переход (`FsmTransition`): event, guard, actions, `to` |
| Маршрут (`Route`) | вычисленная ортогональная ломаная. **Не сохраняется** |
| Опорная точка (`Waypoint`) | мягкое предпочтение на переходе (`waypoints[]`) |
| Запретная зона (`Obstacle`) | bounds узла + `NODE_ROUTING_PADDING` |

Пользователь управляет структурой автомата и расположением состояний. Система отвечает за геометрию стрелок.

Типы блоков из ТЗ (действие, ожидание, условие, событие, начало/завершение) — **будущие визуальные виды состояния**, а не отдельные смысловые сущности runtime. Runtime по-прежнему исполняет `states[]`.

```text
Graph Model (FSM states + transitions)
    ↓
Layout Engine          — только по команде Auto-layout
    ↓
Routing Engine         — после любого изменения геометрии
    ↓
Geometry Validation
    ↓
Renderer (SVG + HTML)
```

### Решения v1

| Тема | Решение |
|------|---------|
| Тип маршрута | ортогональный (H/V), прямой — частный случай |
| Маршрутизатор | собственный A* по сетке Ханана; библиотека не подключена |
| Auto-layout | слоистый longest-path; не запускается сам при drag |
| `routing_mode` | только `automatic` |
| Пересечения связей | минимизация стоимостью + ореол линии, чтобы пересечение не выглядело соединением |
| Направление потока | `vertical` по умолчанию; `horizontal` — предпочтение маршрутизатора |
| Сохранение | позиция/размер узла, порты, waypoints. SVG-path не сохраняется |

Первая версия **не включает:** свободное рисование кривых, ручное редактирование каждого сегмента, `locked_route`, совместное редактирование, семантические коридоры по типам FSM.

---

## 1. Цель

Пользователь размещает блоки FSM на бесконечном холсте, соединяет их переходами и меняет структуру машины, при этом:

* блоки не перекрывают друг друга в нормальном состоянии;
* связи корректно прокладываются между блоками;
* связи не проходят через блоки;
* маршруты перестраиваются при изменении схемы;
* подписи переходов остаются читаемыми;
* пользователь управляет структурой и композицией, а не вручную исправляет геометрию каждой стрелки;
* сложные ветвления и циклы остаются визуально понятными.

### Не является целью

Создание универсального аналога FigJam. Редактор — **структурный графовый редактор с поведением, ориентированным на FSM**.

---

## 2. Основные понятия

### 2.1. Узел (`Node`)

Визуальный блок FSM. На холсте v0.1 это состояние.

Каждый узел имеет: идентификатор, позицию, размер, визуальное представление, порты, ограничения размещения.

### 2.2. Порт (`Port`)

Точка входа/выхода связи. Направления: `top` | `right` | `bottom` | `left`.

Если пользователь явно выбрал порт (или система уже назначила его связи), выбор сохраняется. Иначе выбирает автоматически **один раз** — при создании связи или при первой отрисовке. Перемещение и ресайз узла порты не меняют: перестраивается только ломаная. Порты переназначаются при Auto-layout и когда пользователь перетаскивает конец стрелки.

### 2.3. Связь (`Connection`)

Смысловой переход между двумя узлами. Существует независимо от визуального маршрута. Удаление маршрута не удаляет связь.

### 2.4. Маршрут (`Route`)

Вычисленная геометрия связи: последовательность точек и ортогональных сегментов.

**Маршрут не является самостоятельным смысловым объектом.**

### 2.5. Опорная точка (`Waypoint`)

Мягкое предпочтение пользователя относительно прохождения маршрута. Не должна нарушать геометрические инварианты.

### 2.6. Запретная зона (`Obstacle`)

```text
obstacle = node_bounds + routing_padding
```

Маршрутизатор не прокладывает сегменты через запретные зоны. Для узлов-терминалов связи запретна только внутренняя область узла (чтобы выйти из порта).

---

## 3. Принципы

### 3.1. Разделение смысла и геометрии

Пользователь создаёт связь между узлами. Система назначает порты, если они ещё не заданы, считает маршрут и место подписи. После изменения геометрии перестраивается маршрут; порты остаются, пока пользователь сам не сменит их или не вызовет Auto-layout.

### 3.2. Геометрические инварианты имеют приоритет

1. Связь не пересекает узлы.
2. Связь начинается и заканчивается на допустимых портах.
3. Маршрут не содержит самопересечений.
4. Подписи не перекрывают узлы.
5. Маршрут остаётся в допустимой области отображения.
6. Все существующие связи имеют корректную отображаемую геометрию.

Если старый маршрут нарушает условия, система обязана перестроить его.

Пересечение узла — **недопустимое** состояние, а не дорогой маршрут.

### 3.3. Пользователь сохраняет контроль над композицией

Система не перемещает существующие узлы при пересчёте маршрута. Автоматическая раскладка — отдельная команда.

При обычном перемещении узла система:

* перестраивает затронутые связи, **не меняя порты**;
* показывает направляющие;
* может предлагать выравнивание и привязку к сетке;
* не перестраивает всю схему без команды.

---

## 4. Модель данных

Позиция и размер узла хранятся в координатах холста раздельно. Размер не меньше минимального и должен вмещать содержимое.

Связь ссылается на порт, не только на сторону. `route` на диске не хранится.

```text
Node        id, type=state, position, size, min_size, ports[]
Port        id, node_id, direction, position, allowed_connections
Connection  id, source/target node+port, type, label, routing_mode, waypoints[]
```

---

## 5. Размещение узлов

Узлы — прямоугольники для геометрических расчётов. В нормальном состоянии не пересекаются. Между ними — минимальный визуальный интервал. Ресайз инициирует пересчёт связей.

```text
MIN_NODE_GAP = 40 px
NODE_ROUTING_PADDING = 20 px
```

Значения конфигурируемые.

При перемещении: предпросмотр позиции, связи остаются видимыми, направляющие и snap к сетке/другим узлам. Другие узлы сами не едут.

По завершении:

1. проверить пересечение;
2. если запрещено — ближайшая допустимая позиция либо конфликт;
3. перестроить затронутые связи;
4. проверить инварианты.

Выравнивание: левый/правый/центр/верх/низ край, равные интервалы. Доступно через направляющие, отдельную команду и auto-layout.

---

## 6. Направление схемы

Предпочтительное направление основного потока: `vertical` (по умолчанию) или `horizontal`.

Это предпочтение маршрутизатора, не жёсткое ограничение.

* vertical: основной поток сверху вниз, ветки в стороны, возвраты обходят композицию;
* horizontal: основной поток слева направо, ветки вверх/вниз, возвраты обходят композицию.

---

## 7. Маршрутизация

Ортогональный маршрут. Не допускается: прохождение через узлы, самопересечения, неконтролируемые кривые, маршруты, которые нельзя проверить на пересечение.

Порядок:

```text
1. источник и назначение
2. порты
3. запретные зоны
4. карта свободного пространства (сетка Ханана)
5. допустимые направления выхода
6. возможные маршруты (A*)
7. стоимость
8. минимум стоимости
9. удаление лишних изгибов
10. проверка пересечений
11. размещение подписи
12. результат; если нет — fallback, иначе состояние проблемы
```

Приоритеты стоимости:

1. корректность (не через узлы) — hard constraint
2. меньше пересечений связей
3. защитные отступы
4. длина
5. меньше изгибов
6. направление потока

```text
cost = route_length
     + bends * BEND_PENALTY
     + crossings * CROSSING_PENALTY
     + proximity * PROXIMITY_PENALTY
     + direction_deviation * DIRECTION_PENALTY
```

---

## 8. Запретные зоны

Защитный отступ конфигурируемый. Изменение размера/позиции узла меняет зону. Проверка пересечений использует запретные зоны, не только визуальную рамку.

---

## 9. Пересечения связей

Минимизировать, но не гарантировать нулевое число в любом графе.

v1: стоимость пересечения в маршрутизаторе + ореол линии. Не допускается наложение без различения и пересечение, которое выглядит как соединение.

---

## 10. Возвратные связи и циклы

Циклы для FSM нормальны. Если связь возвращается к узлу выше или левее источника, маршрутизатор по возможности выводит её во внешний коридор и не прорезает центр схемы без необходимости.

Смысловые коридоры (`normal_transition`, `error_transition`, `return_transition`, `cancel_transition`) — архитектурный задел, не полноценная реализация v1.

---

## 11. Подписи связей

Самостоятельный визуальный объект: геометрия, область столкновения, правила размещения.

Подпись не пересекает узлы и другие подписи, не стоит на изгибе, сидит на прямом сегменте достаточной длины, сохраняет читаемую ориентацию и не закрывает стрелку.

Длинная подпись: другой сегмент → компактная карточка → полный текст по наведению/выбору. Подпись не имеет права ломать геометрические инварианты.

---

## 12. Опорные точки

Сохраняются при пересчёте. Не пересекают запретные зоны и не заставляют маршрут идти через узлы. Если сохранить нельзя — маршрут меняется либо показывается конфликт. По умолчанию мягкие. `locked_route` — будущее; даже тогда инварианты важнее фиксации.

---

## 13. Автоматическая раскладка

Маршрутизация ≠ раскладка. Режимы: Manual / Assisted / Auto-layout.

Auto-layout учитывает направление потока, циклы, ветвления, размеры, интервалы; после себя пересчитывает маршруты; **не** запускается после каждого drag.

---

## 14. Проверка геометрии

После каждого изменения, влияющего на геометрию: `validate_graph_geometry()`.

Узлы: нет пересечений, корректный размер, допустимые координаты.  
Связи: концы существуют, порты существуют, маршрут есть, не пересекает узлы, без самопересечений, старт/финиш корректны.  
Подписи: не на узлах, не на других подписях, не на изгибе.

Если маршрут не построен: альтернатива → безопасный fallback → явное состояние проблемы. Молча показывать некорректную стрелку нельзя.

---

## 15. Перерисовка

При перемещении узла пересчитываются исходящие, входящие и задетые маршруты плюс их подписи. Полный пересчёт — при auto-layout, массовом изменении, смене глобальных параметров.

Во время drag допускается упрощённый маршрут. После отпускания — полный пересчёт затронутых.

---

## 16. Визуальные требования

Связи: заметное направление, стрелка на конце, старт от порта, не под узлами, не сливаются, читаемы при масштабе.

Узлы: различимая граница, область захвата, видимые порты при подключении, состояния выделения и перемещения.

Холст: панорама, масштаб, выделение узлов и связей, перемещение узлов, создание и удаление связей, auto-layout.

---

## 17. Критерии приёмки

1. **Простая связь** — соединяет порты, не пересекает узлы.
2. **Перемещение назначения** — маршрут перестраивается, не через узлы.
3. **Препятствие** — третий узел на прямом пути → обход.
4. **Ветвление** — связи не сливаются в одну линию.
5. **Цикл** — возврат по внешнему маршруту, если возможно.
6. **Ресайз** — связи не пересекают новый размер.
7. **Подпись** — длинная подпись не перекрывает узлы и читаема.
8. **Опорная точка** — предпочтение сохраняется, инварианты важнее.
9. **Auto-layout** — читаемая композиция, связи пересчитаны.
10. **Сложный граф** — ветки, циклы, параллельные связи различимы и не идут через узлы.

---

## 18. Вне первой версии

Универсальный редактор фигур, свободные кривые, сложные пользовательские ограничения маршрутов, ручное редактирование сегментов, идеальное решение всех пересечений, семантическая раскладка по типам FSM, перестроение всей схемы на каждый drag, realtime collaboration.

---

## Итоговая формулировка

> Редактор представляет FSM как граф узлов и смысловых связей. Узлы имеют геометрию и порты. Связи не хранятся как произвольные линии, а маршрутизируются автоматически по свободному пространству. Маршрутизатор обязан избегать пересечения узлов, учитывать защитные зоны, минимизировать пересечения связей и поддерживать читаемое направление потока. Пользователь управляет структурой и расположением узлов, а система отвечает за корректность геометрии. Автоматическая раскладка является отдельным режимом и не должна лишать пользователя контроля над композицией.
