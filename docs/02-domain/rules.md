# Rules — правила и инварианты

> Уровень: **Что обязано выполняться**. Правила собраны из спек `docs_old/*_SPEC_v0.1.md`, `INTERACTION_SPEC_v0.1.md` и проверены по коду. Оценка: **держится** (код обеспечивает), **частично** (обеспечено прокси/соглашением), **нарушено** (код противоречит), **не обеспечено** (только договорённость, проверки нет).

## R-A. Границы сущностей

| # | Правило | Оценка | Чем обеспечено / где нарушено |
|---|---|---|---|
| A1 | Skill ссылается только на **id Action**; Tool из FSM не вызывается | держится | валидация `unknown_action`; FSM не знает про инструменты |
| A2 | Action скрывает рецепт от FSM: FSM видит только `action.<id>.completed` и `result` | держится | синтез события завершения; шаги не видны автомату |
| A3 | Tool не содержит бизнес-логики и не управляет FSM; события инструмента публикуются runtime | частично | архитектурно так; но LLM-заглушка содержит демо-эвристику «гриб → уточнить», а презенс/ярлыки скиллов захардкожены в коде |
| A4 | Tool type ≠ Tool instance; recipe ссылается на инстанс (или на тип при единственном инстансе) | держится | алгоритм A3; ошибки `ambiguous_tool_reference` |
| A5 | Definition ≠ Runtime: публикация неизменяема; runtime читает публикацию, не черновик | держится | отдельная таблица публикаций; загрузка только из публикации |
| A6 | Запущенный run исполняется по закреплённой версии | держится | `publication_version` на run; resume через закреплённую публикацию |

## R-B. События

| # | Правило | Оценка | Комментарий |
|---|---|---|---|
| B1 | Event — факт, а не команда; имя `<domain>.<entity>.<past_verb>` | **нарушено** в одном месте | диспетчер **переписывает** тип `channel.message.received` → `ui.request.parse_requested` / `human.request.reviewed` по тексту фразы (`INTERACTION_NOTES_ARCHITECTURE_REVIEW.md` §15 R10.3) |
| B2 | Конверт: `id, type, version, source, timestamp, correlation, payload, metadata, causation_id` | держится | валидация конверта при публикации в шину |
| B3 | Дедупликация по стабильному `id`; доставка at-least-once | держится | множество обработанных id; consumer group с ack после обработки |
| B4 | `correlation` ≠ `causation`: первое — контекст, второе — прямая причина | держится | отдельные поля; `causation_id` ставится на `action.<id>.completed` |
| B5 | Completion-событие для FSM — `action.<action_id>.completed`; generic `action.completed` — только observability | держится | бланковое `action.completed` не порождается вовсе |
| B6 | Канон human-событий — `human.request.approved` / `.rejected` / `.corrected` | **расходится** | каталог содержит `approved`/`corrected`; диспетчер и сценарий supplier используют `human.request.reviewed` с `payload.decision` — тип, который спека объявила заменённым |
| B7 | Транспортные заголовки `agentSlug`/`skillId` — не часть доменного конверта | держится | отделяются при чтении из шины |

## R-C. Автомат и процесс

| # | Правило | Оценка | Комментарий |
|---|---|---|---|
| C1 | Один FSM на Skill, один `initial` | держится | `missing_initial`/`invalid_initial` |
| C2 | Несколько handler-ов одного события — по порядку, детерминированно | держится | первый с истинным guard; предупреждение `ambiguous_guards` |
| C3 | Порядок применения: actions перехода → смена состояния → `onEnter` → (completion-события) | держится | см. mechanics M5 |
| C4 | Ожидание — состояние run, не Action; Action короткий | держится | `waiting` на run; у Action только `timeoutMs` |
| C5 | `final` завершает run; `waiting` — не-final без подходящего события | держится | — |
| C6 | No-match доменного события на существующем run ≠ ошибка | держится | run остаётся в прежнем статусе, лог info |
| C7 | Guards — безопасный язык без исполнения кода | держится | regex-грамматика, нет `eval` |
| C8 | `params` — неизменяемое намерение; `vars` — изменяемое состояние | **частично** | в коде `params` тоже обновляются при синхронизации correlation; `required` у params не проверяется |
| C9 | Статусы `CREATED → RUNNING → WAITING → COMPLETED | FAILED | CANCELLED` | **расходится** | нет `created`; `failed` назван `error`; из `error` возможен возврат в `running` |

## R-D. Разговор, работа, стол (Interaction)

Честная матрица приёмки §16 (из `INTERACTION_NOTES_ARCHITECTURE_REVIEW.md` §14, подтверждено кодом): **2.5 / 6**.

| # | Правило / критерий | Оценка | Комментарий |
|---|---|---|---|
| D1 | `conversation_id` — адрес голоса, **не** владелец run; 1 разговор → 0..N работ | держится | поиск ждущих run по разговору фильтруется по `event.type` текущего состояния |
| D2 | Ждущий чат не перехватывает жест (кнопку) только из-за общего `conversation_id` (Q3) | держится | механика M3 п.2 |
| D3 | Вопрос мимоходом не срывает идущий разбор (Q1) | держится | разные скиллы — разные ключи блокировки; класс `side_question` |
| D4 | Кнопка «разобрать» и фраза «разбери» — одна семья работ (Q2) | частично | да, если есть фокус/сущности; без них — `underspecified` |
| D5 | Уточнение видно на карточке и в чате; любой ответ закрывает ожидание (Q4) | **не обеспечено** | «да» → review при любой рабочей run (слишком широко); короткий ответ не доходит до работы, если состояние не ждёт чат; якоря на карточке нет |
| D6 | «Сначала Север» меняет идущий пакет (Q5) | частично | реализовано как cancel + start; история старого run теряется |
| D7 | После ручной правки агент говорит новую цифру (Q6) | **не обеспечено** | снимок стола накладывается на vars; речь по `web.state.changed` не порождается |
| D8 | Стол — источник правды; runtime не ERP | держится | стол живёт в веб-клиенте, runtime читает snapshot и шлёт патчи |
| D9 | Акт имеет актёра; конфликт двух голосов — не last-write-wins | не обеспечено | актёр — строка `user_id`; правил конфликтов нет |
| D10 | Решение диспетчера не уничтожает факт события | нарушено | см. B1 (rewrite); оригинальный тип сохраняется лишь в `metadata.dispatch.rewritten_from` |

## R-E. Надёжность

| # | Правило | Оценка | Комментарий |
|---|---|---|---|
| E1 | Повторная доставка не повторяет побочные эффекты | частично | дедуп по `event.id` до обработки; но при падении **после** побочного эффекта и до `mark_processed` эффект повторится |
| E2 | Сериализация внутри ключа работы/сущности, не всего разговора | держится | ключ `conv-skill:*` |
| E3 | Оптимистичная блокировка run по `revision` | держится | конфликт → повтор сообщения |
| E4 | Run переживает рестарт | держится | durable хранилище, stateless worker |
| E5 | Retry/timeout на уровне исполнения | частично | есть у Action/Tool; нет auto-retry Skill; `expires_at` не проверяется |
| E6 | Crash-recovery середины Action Run | не обеспечено | записи остаются `running`, автопродолжения нет (RUNTIME_IMPLEMENTATION_STATUS §44) |

## Инварианты данных (Fact)

- `agents.slug` уникален; `(agent_id, version)` публикации уникальны.
- `skill_runs.revision` монотонно растёт на каждом сохранении.
- `tool_executions.action_run_id` всегда ссылается на существующий Action Run (создаётся только при известном id).
- Удаление агента каскадно удаляет черновик, публикации, credentials, логи; **не** удаляет `skill_runs` (нет FK) — остаются «сиротами» с `agent_slug`.
