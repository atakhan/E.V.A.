> Зафиксировано 2026-11-06 по итогам продолжения после handoff орбит (`constructor-orbit-ui-handoff.md`).  
> Разделение: **Fact** — что есть в коде и переписке; **Interpretation** — оценка и выводы впрок.

Связанные каноны: [`../01-concept/spatial-ui-principles.md`](../01-concept/spatial-ui-principles.md), черновик режима [`memory-constructor-draft.md`](./memory-constructor-draft.md).

## 1. Что сделали (Fact)

### Каналы и взаимодействие агентов

1. **Ракурс канала.** Канал = инструмент с командами; адреса = пиры (кто может обмениваться с агентом по настройкам коннекта). Свободный граф связей важнее списка «кому можно подключаться к Еве».
2. **Плагин `agents`.** World-tool: `send_message` к агенту по slug; доставка через `accepts` / `agent.message.*`; политика allow inbound/outbound из манифеста.
3. **`memory.interaction`.** Манифест взаимодействия — долговременная часть памяти агента (`peers[]`, defaults). Синхронизируется с адресами `world` (`toolId: agents`).
4. **Дефолт Ева ↔ runtime.** При создании/ensure проекта — двусторонняя связь на канале «Агенты».
5. **Навык «Жизнь» (`life`).** Пустой системный каркас у всех агентов + backfill `ensure_life_skill_on_agents` на старте и при GET агентов.

Канал `project` (коннектор проект↔проект) не снимали — рядом живёт свободный `agents`.

### Конструктор памяти (UI)

1. Память — **режим масштаба**, не боковая панель: карточка летит в центр.
2. Семь задач органа памяти → сателлиты:

| Id | Роль |
|----|------|
| `self` | знание о себе |
| `life` | история жизни (main log) |
| `outcomes` | достижения/провалы |
| `tasks` | актуальные задачи |
| `others` | знания о других (+ манифест) |
| `skills` | знания навыков / куски при установке |
| `focus` | зона внимания (ёмкость сцены, не тип знания) |

3. **Орбита.** Полный круг; радиус center→center = **3 × иконка**.
4. **Слой полки.** Клик по сателлиту — one-pass: раздел → центр; остальные схлопываются в «Память»; справа колонка карточек (`MemoryFacetCards`). Не оверлей-панелька.

### Концептуальные инварианты (договорено в чате)

- Вехи (`outcomes`) появляются **только** когда навык сам пишет в память через Actions работы с памятью; статус прогона сам по себе веху не ставит.
- Навык ↔ память: установка может класть куски; в работе навык читает/пишет.
- «Жизнь» — естественный кандидат на хозяина main log (пока каркас пустой).

### Код (ориентиры)

- Backend: `definition/interaction_manifest.py`, `tools/agents/`, `system_skills` (`life`), ensure на create/startup/API.
- Frontend: `memory/utils/memoryOrbit.ts`, `MemoryFacetCards.vue`, `ConstructorView` (`memoryStage` / `memoryFacet*`).
- Docs: этот файл, `memory-constructor-draft.md`, правки `entities.md`, `spatial-ui-principles.md`, handoff.

## 2. Оценка (Interpretation)

### Что получилось сильно

1. **Сначала ракурс, потом сущность.** Сдвиг «канал = tool, адрес = пир» снял спор «только runtime или fork» и открыл свободный граф.
2. **Память как орган, не лог.** Семёрка задач дала структуру стола раньше полной реализации Actions.
3. **Тот же motion-язык.** Memory → facet повторяет channel → layer: one-pass, collapse в якорь, flyer focus-exempt, контент справа карточками.
4. **Инвариант вех** назван до кода записи — меньше риска сделать «авто-статус прогона = достижение».

### Где хрупко / долг

1. **`ConstructorView` ещё толще** — memory + facet state рядом с channel/layer.
2. Черновые мосты: life ← runtime events, tasks ← active runs; полки self/outcomes пустые до Actions.
3. `MemoryOrbitDetail` устарел относительно `MemoryFacetCards` (слой справа).
4. Нет ещё: memory tool/Actions, установка навыка → куски памяти, отдельный main log vs event stream.

### Процесс

Снова сработало: **инвариант → каркас UI → не прыгать в полный backend**.  
Плотность орбиты: сначала ошиблись с tight packed, потом круг 3×icon — явный критерий владельца лучше «как у агентов» вслепую.

## 3. Что хранить как постоянные правила

1. Канал = команды; адрес = пир; манифест взаимодействия ⊂ память агента.
2. Память в конструкторе = масштаб стола + полки органа + зона внимания как ёмкость.
3. Слой полки: flyer в центр, остальные за/в память, содержание — **карточки справа**, не сайдбар.
4. Орбита полок памяти: круг, радиус **3 иконки**.
5. Outcomes пишет только навык (memory Actions).
6. One-pass / handoff / focus-exempt — те же, что для channel/desk.
